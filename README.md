# Праздники события

Сайт о праздниках: Новый год 2027, рецепты праздничного стола и конкурсы.
Готовые меню, списки продуктов, граммовки и идеи для гостей. Чистый
фронтенд — HTML, CSS и немного JavaScript. Без сборки, зависимостей
и внешних запросов: страницы открываются двойным кликом по `index.html`
и одинаково работают без интернета.

## Как открыть

- **Просто:** двойной клик по `index.html` — откроется главная страница.
- **Как на GitHub Pages:** локальный сервер из корня проекта:

  ```bash
  python3 -m http.server 8000
  ```

  затем <http://localhost:8000/>.

## База рецептов

Рецепты живут в `data/recipes.json` — это единственный источник данных.
Сейчас в базе **500 рецептов** шестнадцати заполненных категорий, шести кухонь.
Страница `recipes/index.html` ничего не хранит в разметке: карточки, фильтры
по кухне и типу блюда, выбор рецептов, код подборки и модальное окно строятся из JSON.

### Категории, кухни и способы приготовления

Заполнены шестнадцать категорий. В салатах, свинине, курице и говядине —
по 50 рецептов, в остальных двенадцати категориях — по 25.

Счётчики в фильтрах зависимые: при выбранной кухне «Тип блюда» показывает
реальное количество блюд этой кухни, а при выбранном типе — количество
блюд этой категории по кухням. Поиск тоже учитывается. Нулевые варианты
остаются в списке, но неактивны; если выбранная комбинация стала нулевой,
зависимый фильтр автоматически сбрасывается.

Способы приготовления: `kazan` — казан (61), `mangal` — мангал (18),
`plita` — плита и духовка (419), `tandyr` — тандыр (2). Способ хранится
в поле `method` и выводится тегом на карточке. Кнопки «Способ
приготовления» работают как дополнительный фильтр: можно выбрать
несколько способов одновременно, тогда показываются рецепты любого
из выбранных.

Ниже — блок «Теги». После приведения однокоренных форм к одному виду
в базе осталось 231 уникальный тег; в блоке показываются только теги,
которые встречаются минимум в 5 рецептах (74 штуки). Теги с одним–четырьмя
рецептами в блок не попадают, но остаются на карточках и в данных. Теги выводятся
кнопками с количеством рецептов; выбранные теги работают по принципу
«И» — показываются рецепты, у которых есть все отмеченные теги.
Счётчики учитывают поиск, кухню, тип блюда, способ приготовления
и другие выбранные теги. В блоке есть поиск по тегам и кнопка сброса;
список прокручивается, чтобы не растягивать страницу.

Кухни:

- `russian` — русская (116 рецептов);
- `european` — европейская (121);
- `caucasian` — кавказская (87);
- `central_asian` — среднеазиатская (54);
- `middle_eastern` — ближневосточная (60);
- `balkan` — балканская (62).

### Почему два файла

`fetch('data/recipes.json')` не работает при открытии страницы двойным кликом
(`file://`): браузеры блокируют чтение локальных файлов. Поэтому рядом лежит
`data/recipes.bundle.js` — тот же JSON в виде `window.RECIPE_DB`, который
подключается обычным `<script>` и работает офлайн. Страница подключает бандл
всегда: так данные гарантированно доступны и по `file://`, и на GitHub Pages.
Если бандла нет, на `http(s)` слой данных пытается загрузить сам `recipes.json`
через `fetch`.

Бандл генерируется, вручную его не правят:

```bash
python3 tools/sync_recipes.py          # проверить JSON и пересобрать бандл
python3 tools/sync_recipes.py --check  # проверить, что бандл не отстал
```

Скрипт проверяет обязательные поля, уникальность `id`, непустые шаги,
числовые количества, существование категорий, праздников, кухонь и способов приготовления,
а также обязательный вес или объём готового блюда `yield` в формате `450 г`, `1,2 кг`, `250 мл` или `1,5 л`.

### Структура записи

```json
{
  "id": "olivier",
  "title": "Салат «Оливье» с говядиной",
  "category": "salad",
  "cuisine": "russian",
  "method": "plita",
  "holidays": ["new_year", "birthday"],
  "tags": ["мясное", "классика"],
  "description": "…",
  "servings": 8,
  "yield": "1,7 кг",
  "time": { "prep": 30, "cook": 40 },
  "difficulty": "easy",
  "allergens": ["яйца", "горчица"],
  "storage": "в холоде до 12 часов",
  "ingredients": [
    { "name": "Говядина (мякоть)", "amount": 400, "unit": "г", "note": "отварная" },
    { "name": "Соль", "amount": null, "unit": "", "note": "по вкусу" }
  ],
  "steps": ["Отварить говядину…", "Нарезать кубиком…"],
  "tips": "…"
}
```

- `id` — латиница в нижнем регистре, используется в ссылках
  (`recipes/index.html#olivier`);
- `amount: null` — «по вкусу» (текст берётся из `note`);
- `category`, `cuisine`, `method` и `holidays` ссылаются на списки в начале файла;
- `yield` — обязательный вес или объём готового блюда (не сумма сырых ингредиентов);
- `cuisine` — `russian`, `european`, `caucasian`, `central_asian`, `middle_eastern` или `balkan`;
- `method` — `kazan`, `mangal`, `plita` или `tandyr`.

### Как добавить рецепт

1. Добавить объект в конец массива `recipes` в `data/recipes.json`
   (порядок записей важен для старых кодов подборок — см. ниже).
2. Запустить `python3 tools/sync_recipes.py`.
3. Открыть `recipes/index.html` — карточка и фильтр появятся сами.

`cuisine` и `yield` обязательны. Все категории уже заполнены; новые
рецепты автоматически попадут в фильтры по кухне и типу блюда.

## Выбор рецептов

На каждой карточке рецепта есть звезда:

- контурная — рецепт не выбран;
- заполненная — рецепт в выбранных.

Клик по звезде добавляет рецепт в подборку или убирает его. Внизу
открытого рецепта есть кнопка «Выбрать» со звездой — рядом с кнопкой
«Закрыть». Режим «Выбранные» показывает только карточки
выбранных блюд; поиск и фильтры по кухне, типу блюда и способу
приготовления работают и там.

Кнопка «Сбросить выбранные» рядом с вкладками очищает подборку, код и
параметр `?code` в адресе. На широком экране фильтры кухни и типа блюда
стоят в одной строке с кнопкой «Поделиться»; на телефоне они
перестраиваются в столбец.

## Ссылка на подборку

При выборе рецептов страница формирует самодостаточный код вида `HV1-…`.
Сам код не показывается: вместо него в строке фильтров есть кнопка
«Поделиться» с количеством выбранных блюд. Код не хранится на сервере:
внутри — битовая маска выбранных рецептов и контрольная сумма. Поэтому
ссылка работает на другом устройстве, в другом браузере и без интернета.

- Пока ничего не выбрано, кнопка «Поделиться» неактивна.
- После выбора рядом с надписью появляется число: 1, 2, 10 и т.д.
- Кнопка копирует полный адрес страницы с `?code=…`, например
  `https://<логин>.github.io/holiday_vault/recipes/?code=HV1-…`.
- На мобильном телефоне открывается системное окно «Поделиться» через
  мессенджеры. На десктопе появляется короткое уведомление о том, что
  ссылка скопирована в буфер обмена.
- При открытии такой ссылки страница автоматически применяет код,
  переключается в режим «Выбранные» и показывает те же блюда.
- Код в адресе обновляется при каждом выборе или снятии рецепта; когда
  снят весь выбор, параметр `code` удаляется.

Кодек можно проверить отдельно, без браузера:

```bash
node tools/test_selection_code.js
```

Код привязан к порядку рецептов в `data/recipes.json`: **новые рецепты
добавляйте только в конец массива**, существующие не переставляйте.
Иначе старые ссылки могут показать другой набор.

## База конкурсов

Конкурсы живут в `data/contests.json` — это единственный источник данных.
Сейчас в базе **200 конкурсов**: по 25 в каждом из 8 типов, включая **20 новогодних**. Страница
`contests/index.html` не хранит карточки в разметке — фильтры, карточки,
правила и реквизит строятся из JSON.

Типы: застольные, активные, интеллектуальные, творческие, музыкальные,
театральные, кулинарные и квесты. Аудитории: детские, подростковые,
взрослые, семейные и для пар. У конкурса может быть несколько аудиторий.
Дополнительно в карточке есть возраст, время, число участников, формат
(индивидуальный, командный, парный), реквизит и теги.

Фильтры «Тип конкурса» и «Для кого» считают реальные количества с учётом
другого фильтра. Нулевые варианты остаются в списке, но неактивны;
несовместимая пара автоматически сбрасывает зависимый фильтр.

Ниже выводятся все теги из карточек в виде кнопок с множественным выбором.
Выбранные теги работают по принципу «И»: показываются конкурсы, у которых
есть все отмеченные теги. Счётчики тегов учитывают тип, аудиторию и другие
выбранные теги; нулевые кнопки неактивны. Если после смены типа или
аудитории выбранные теги перестают давать результат, лишние сбрасываются.

Данные устроены так же, как у рецептов:

```json
{
  "id": "table-ugaday-blyudo",
  "title": "Угадай блюдо",
  "type": "table",
  "audiences": ["kids", "family", "adults"],
  "minAge": 6,
  "duration": 10,
  "players": "4–12 человек",
  "format": "individual",
  "props": [],
  "tags": ["весёлый", "без реквизита"],
  "description": "…",
  "rules": ["…", "…", "…"],
  "tip": "…"
}
```

`data/contests.bundle.js` — тот же JSON в виде `window.CONTEST_DB` для
работы по `file://`. Бандл пересобирается скриптом:

```bash
python3 tools/sync_contests.py          # проверить JSON и пересобрать бандл
python3 tools/sync_contests.py --check  # проверить, что бандл не отстал
```

Скрипт проверяет схему полей, уникальность `id` и названий, ссылки на типы
и аудитории, формат `rules`, `format`, `props`, общее число конкурсов,
по 25 конкурсов в каждом типе и количество новогодних (20).

### Дорожная карта

Слой данных (`js/recipe-store.js`) не привязан к странице рецептов: раздел
праздника сможет отрисовать блюда из базы вызовом `RecipeStore.byIds([...])`.
Сейчас `new_year/index.html` остаётся со своей вёрсткой рецептов — это
осознанный шаг, который закроется, когда меню начнёт собираться из базы.

## Публикация на GitHub Pages

1. Репозиторий → **Settings** → **Pages**.
2. **Source**: *Deploy from a branch*.
3. **Branch**: `main`, **Folder**: `/ (root)` → **Save**.
4. Через минуту сайт будет доступен по адресу
   `https://<логин>.github.io/holiday_vault/`.

Обновления появляются после `git push` автоматически (около минуты).
Файл `.nojekyll` уже добавлен, поэтому GitHub Pages отдаёт файлы как есть.

## Как добавить раздел

1. Создать папку раздела, например `contests/`, и положить в неё `index.html`.
2. Стили раздела — отдельным файлом в `css/` (например, `css/contests.css`),
   общие токены и сброс уже есть в `css/base.css`.
3. Иллюстрации — в `images/previews/` (превью карточки) и `images/`.
4. Добавить на главной странице карточку-ссылку:

   ```html
   <li class="card-item">
     <article class="event-card">
       <a class="event-link" href="contests/index.html"> … </a>
     </article>
   </li>
   ```

5. Добавить на новой странице ссылку
   `<a class="back-link" href="../index.html">← На главную</a>`.

## Адаптивность и формат

Главный формат — мобильный телефон. Сайт должен быть удобен в первую очередь
на узком экране; десктопная версия вторична, но не теряет функций.

- Мобильно-первый CSS: базовые правила рассчитаны на телефон, дальше идут
  брейкпоинты `min-width: 600px` и `min-width: 900px`.
- Сетка карточек — `repeat(auto-fill, minmax(min(100%, 280px), 1fr))`:
  1 колонка на телефоне, 2 на планшете, 3 на десктопе.
- Тач-цели (кнопки и ссылки) — не меньше 44 px по высоте.
- Таблицы новогодней страницы на узких экранах переносят текст и уменьшают
  отступы, чтобы не появлялся горизонтальный скролл.
- Проект проверен на ширинах 360, 390, 768, 1024 и 1440 px.

## Доступность и детали

- Контраст текста: основной `#2b3a42` на светлом фоне — около 11:1,
  вторичный `#556770` — около 5,7:1 (норма AA).
- Есть ссылка «Перейти к содержимому», видимый фокус, скрытый заголовок
  раздела для скринридеров.
- Главная полностью статична: три карточки-ссылки и никаких фильтров.
  Поиск и код подборки есть только на странице рецептов, фильтры —
  на страницах рецептов и конкурсов.
- Учитывается `prefers-reduced-motion`; есть стили для печати.
- Шрифты — системные, поэтому каталог `fonts/` пока пуст: подробности
  и ограничения `file://` — в `fonts/README.md`.
