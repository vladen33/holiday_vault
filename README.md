# holiday_vault

Каталог праздников и событий: готовые меню, списки продуктов и планы подготовки.
Чистый фронтенд — HTML, CSS и немного JavaScript. Без сборки, зависимостей
и внешних запросов: страницы открываются двойным кликом по `index.html`
и одинаково работают без интернета.

## Структура

```
holiday_vault/
├── index.html            главная — каталог праздников
├── 404.html              страница «не найдено» для GitHub Pages
├── .nojekyll             отключает обработку Jekyll на GitHub Pages
├── css/
│   ├── base.css          токены палитры, сброс, базовая типографика
│   ├── home.css          оболочка и стили каталога (шапка, фильтры, карточки)
│   ├── new_year.css      стили страницы Нового года
│   └── recipes.css       стили страницы рецептов и модального окна
├── js/
│   ├── home.js           поиск, фильтры и счётчик карточек каталога
│   ├── recipe-store.js   слой данных: загрузка и выборка рецептов
│   └── recipes.js        страница рецептов: сетка, выбор, модальное окно
├── data/
│   ├── recipes.json      база рецептов — единственный источник правды
│   ├── recipes.schema.json  JSON Schema для редактора
│   └── recipes.bundle.js сгенерированный бандл для file://
├── tools/
│   └── sync_recipes.py   валидация JSON и сборка бандла
├── images/
│   ├── favicon.svg       иконка сайта
│   ├── hero.svg          иллюстрация первого экрана
│   └── previews/         превью карточек каталога (SVG)
├── fonts/
│   └── README.md         каталог под локальные шрифты и ограничения file://
```

Все пути относительные — это обязательно и для `file://`, и для GitHub Pages,
где проект живёт в подкаталоге `/<репозиторий>/`.

## Как открыть

- **Просто:** двойной клик по `index.html` — откроется каталог праздников.
- **Как на GitHub Pages:** локальный сервер из корня проекта:

  ```bash
  python3 -m http.server 8000
  ```

  затем <http://localhost:8000/>.

## База рецептов

Рецепты живут в `data/recipes.json` — это единственный источник данных.
Страница `recipes/index.html` ничего не хранит в разметке: карточки, фильтры,
список выбора и модальное окно строятся из JSON.

### Почему два файла

`fetch('data/recipes.json')` не работает при открытии страницы двойным кликом
(`file://`): браузеры блокируют чтение локальных файлов. Поэтому рядом лежит
`data/recipes.bundle.js` — тот же JSON в виде `window.RECIPE_DB`, который
подключается обычным `<script>` и работает офлайн. На GitHub Pages и локальном
сервере используется сам `recipes.json`.

Бандл генерируется, вручную его не правят:

```bash
python3 tools/sync_recipes.py          # проверить JSON и пересобрать бандл
python3 tools/sync_recipes.py --check  # проверить, что бандл не отстал
```

Скрипт проверяет обязательные поля, уникальность `id`, непустые шаги,
числовые количества, существование категорий и праздников.

### Структура записи

```json
{
  "id": "olivier",
  "title": "Салат «Оливье» с говядиной",
  "category": "salad",
  "holidays": ["new_year", "birthday"],
  "tags": ["мясное", "классика"],
  "description": "…",
  "servings": 8,
  "yield": "1,7 кг",
  "time": { "prep": 30, "cook": 40 },
  "difficulty": "easy",
  "allergens": ["яйца", "горчица"],
  "storage": "в холоде до 12 часов",
  "ingredients": [
    { "name": "Говядина (мякоть)", "amount": 400, "unit": "г", "note": "отварная" },
    { "name": "Соль", "amount": null, "unit": "", "note": "по вкусу" }
  ],
  "steps": ["Отварить говядину…", "Нарезать кубиком…"],
  "tips": "…"
}
```

- `id` — латиница в нижнем регистре, используется в ссылках
  (`recipes/index.html#olivier`);
- `amount: null` — «по вкусу» (текст берётся из `note`);
- `category` и `holidays` ссылаются на списки в начале файла.

### Как добавить рецепт

1. Добавить объект в `recipes` в `data/recipes.json`.
2. Запустить `python3 tools/sync_recipes.py`.
3. Открыть `recipes/index.html` — карточка, фильтр и пункт в списке появятся сами.

Новые категории (закуски, горячее, десерты) уже описаны в `categories`:
как только в них появятся рецепты, они автоматически попадут в фильтры.

### Дорожная карта

Слой данных (`js/recipe-store.js`) не привязан к странице рецептов: раздел
праздника сможет отрисовать блюда из базы вызовом `RecipeStore.byIds([...])`.
Сейчас `new_year/index.html` остаётся со своей вёрсткой рецептов — это
осознанный шаг, который закроется, когда меню начнёт собираться из базы.

## Публикация на GitHub Pages

1. Репозиторий → **Settings** → **Pages**.
2. **Source**: *Deploy from a branch*.
3. **Branch**: `main`, **Folder**: `/ (root)` → **Save**.
4. Через минуту сайт будет доступен по адресу
   `https://<логин>.github.io/holiday_vault/`.

Обновления появляются после `git push` автоматически (около минуты).
Файл `.nojekyll` уже добавлен, поэтому GitHub Pages отдаёт файлы как есть.

## Как добавить новый праздник

1. Создать папку раздела, например `birthday/`, и положить в неё `index.html`
   (копия структуры `new_year/index.html` — самый быстрый путь).
2. Стили раздела — отдельным файлом в `css/` (например, `css/birthday.css`),
   общие токены и сброс уже есть в `css/base.css`.
3. Иллюстрации — в `images/previews/` (превью карточки) и `images/`.
4. На главной странице заменить карточку-заглушку «Скоро» на ссылку:

   ```html
   <a class="event-link" href="birthday/index.html"> … </a>
   ```

   и указать у `li.card-item` атрибуты `data-season` и `data-keywords` —
   по ним работают фильтры и поиск.
5. Добавить на новой странице ссылку
   `<a class="back-link" href="../index.html">← Все праздники</a>`.

## Адаптивность

- Мобильно-первый CSS: базовые правила рассчитаны на телефон, дальше идут
  брейкпоинты `600px` и `900px`.
- Сетка карточек — `repeat(auto-fill, minmax(min(100%, 280px), 1fr))`:
  1 колонка на телефоне, 2 на планшете, 3 на десктопе.
- Тач-цели (кнопки, поиск, ссылки) — не меньше 44 px по высоте.
- Таблицы новогодней страницы на узких экранах переносят текст и уменьшают
  отступы, чтобы не появлялся горизонтальный скролл.
- Проект проверен на ширинах 360, 390, 768, 1024 и 1440 px.

## Доступность и детали

- Контраст текста: основной `#2b3a42` на светлом фоне — около 11:1,
  вторичный `#556770` — около 5,7:1 (норма AA).
- Есть ссылка «Перейти к содержимому», видимый фокус, `aria-live` у счётчика
  карточек, `aria-pressed` у фильтров.
- Поиск и фильтры работают на JavaScript; без JS панель скрыта, но все
  карточки и ссылки доступны.
- Учитывается `prefers-reduced-motion`; есть стили для печати.
- Шрифты — системные, поэтому каталог `fonts/` пока пуст: подробности
  и ограничения `file://` — в `fonts/README.md`.
